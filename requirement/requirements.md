## 1. 背景与目标

### 1.1 问题陈述

现有 EPUB 阅读器在「中文长文阅读」这一核心场景上都存在明显缺陷：

| 现有方案 | 问题 |
|---|---|
| Calibre 阅读器 | 依赖 QtWebEngine（捆绑整个 Chromium），内存 400MB+，启动慢，排版失控 |
| Foliate (GTK4) | 依赖 WebKitGTK，绑定系统库版本；Manjaro 这类滚动发行版每次 webkit2gtk 大版本升级都可能破坏运行 |
| 各类 Electron 阅读器 | 同 Calibre 问题，且中文排版不做避头尾 |
| 各类终端/极简阅读器 | 无中文排版优化（无两端对齐、无避头尾、行距不可调） |

**核心矛盾**：中文排版质量 ↔ 依赖自包含性 ↔ 性能（内存/启动/滚动流畅度）三者不可兼得。

### 1.2 项目目标

构建一个**自包含、高性能、中文排版考究**的桌面 EPUB 阅读器，同时满足：

1. **自包含**：安装后不依赖系统 WebKit/Chromium/GTK 版本；不随系统库滚动升级而损坏。
2. **高性能**：内存占用为 Chromium 方案的 1/3，启动时间为 1/2，滚动与换节稳定 60fps。
3. **排版考究**：中文两端对齐、首行缩进、避头尾（禁则）、可调行距字体，观感接近纸质书。
4. **可控美观**：滚动与整屏切换完全自主（GPU 合成的位图位移），不依赖 CSS 3D 的妥协实现。

### 1.3 成功判据（一句话）

> 用这本书（85MB、408 张图、22,051 字的单节）连续阅读 30 分钟，不卡、不乱、不爆内存，且排版观感优于 Foliate 默认设置。

## 2. 范围

### 2.1 In Scope

- **格式**：EPUB 2.0.1 与 EPUB 3.0+（含 EPUB3 nav 文档与 EPUB2 NCX 目录）
- **内容形态**：纯文字章节、图文混排章节、脚注引用（`aside` + `sup`/`a`）
- **平台**：Linux 优先（Wayland 与 X11 均可），Windows 次要
- **界面**：连续滚动阅读（主）、目录侧栏、本节大纲栏、设置面板、右键菜单
- **交互**：滚轮 / 键盘 / 滚动条滚动，**按住左键拖拽平移**（FR-079），**文本选择与复制**（FR-070：`Shift` 拖拽标记、`Shift` 单击 / 双击取词、`Ctrl+C` 取回）

### 2.2 Out of Scope（明确不做，v1）

| 项 | 理由 |
|---|---|
| 手机 / 平板端 | 用户明确放弃；Qt 移动端会引入额外构建复杂度 |
| 竖排（直排）中文 | Qt 6 无垂直 CJK 排版支持，需自研 shaping，成本不可接受 |
| `ruby` 注音 | Qt 6 不支持 ruby；实测两本目标书均无 ruby |
| 表格阅读 | 实测两本书 `<table>` 数量为 0，投入产出比低 |
| PDF / MOBI / AZW3 / TXT | 聚焦 EPUB，避免格式适配摊薄质量 |
| 在线书城 / 账号 / 云同步 | 非阅读核心 |
| DRM 移除 | 合规风险 |
| 划线 / 笔记 / 批注（v1） | 留给 v2；但架构必须预留（见 NFR-011） |
| 语音朗读（TTS） | 非核心 |
| **跨章节拼接成一列**（越过章末继续滚进下一章的同一条文字流） | 一节 = 一列；拼接两文档要做偏移换算、跨文档图片预取与位置记忆，v1 不做（见架构 ADR-016）。节首改为**常驻位置栏**（写「层次 › 正文名字」，FR-074）、节末改为显式「下一章」入口 |

## 3. 术语表

| 术语 | 定义 |
|---|---|
| **节 (Section)** | 一次排版与缓存单元，对应屏幕上的**一条连续列**；通常就是一个 spine 文档，但当**目录行指向纯图片扉页**时，其后「书没点名、自己也说不出名字」的文档并进同一节（FR-016 / ADR-021） |
| **块 (Block)** | 段落级内容单元（段落 / 标题 / 图片 / 分隔符 / 引用块 / 列表项） |
| **页 (Page)** | ~~节内容按可视区域高度切分后的一个可视单位~~ —— **ADR-016 已废除**：连续滚动列没有页边界，渲染单位是「窗口」 |
| **流 (Span)** | 块内的行内样式片段（粗体 / 斜体 / 颜色 / 锚点 / 上标） |
| **列 (Column)** | 一个节按正文栏宽**连续排版**得到的整条内容；列高由内容决定，**没有页边界**（ADR-016） |
| **窗口 (Window)** | 视口大小的一块位图：高 = 页框高 + 1 个渲染量子（32px）。连续滚动以窗口为单位取景 |
| **页框 (Page box)** | 正文栏中真正可见的文字区域（不含边距）；QML 只贴页框那一块，量子内的位移靠源矩形平移，**不回调 Python** |
| **避头尾** | 中文禁则处理：禁止行首出现 `。，、！？` 等、禁止行尾出现 `《「（` 等 |
| **两端对齐** | 中文段落左右边界同时齐平的排版（`AlignJustify`） |
| **标点挤压** | 连续标点之间的多余空隙收紧 |
| **WJ** | U+2060 WORD JOINER，UAX#14 中显式禁止两侧断行的字符 |

### 4.1 从样本得出的硬性设计输入

| 编号 | 事实 | 对设计的要求 |
|---|---|---|
| I-1 | 25/28 文档无扩展名（如 `xhtml/Chapter4_1`） | **必须按 manifest 的 `media-type` 判定文档类型，严禁依赖文件扩展名** |
| I-2 | 单节最大 22,051 字 / 约 100 段 | 排版引擎必须能承受 2 万字级文档 |
| I-3 | 408 张 900×1400 JPEG 共 85MB；全解码约 408×900×1400×4B ≈ 2.0 GB | **必须按需解码 + LRU 缓存**，常驻图片内存不超过 30MB |
| I-4 | 书名指定的字体 `PingFang SC` / `FZFangSong-Z02` 在 Linux 上**不存在** | **必须丢弃发布者字体声明**，使用自有字体栈 |
| I-5 | 4044 个 `<b>` + 2303 个 `<span>`，无实际语义 | 必须有 HTML 规范化层，塌缩无语义标签 |
| I-6 | EPUB 2 参考书每文档带 70 `<meta>` + 68 `<link>` 样板 | 解析需容忍 XHTML 样板噪声 |

## 5. 功能需求

优先级定义：**P0** = v1 必须，缺任何一个则不可用；**P1** = v1 应有，影响体验完整性；**P2** = v1 可选，锦上添花。

### 5.1 书籍装载

| ID | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| FR-001 | 支持通过命令行参数传入 `.epub` 路径直接打开 | P0 | `ebook-reader book.epub` |
| FR-002 | 解析 `META-INF/container.xml` 定位 OPF 包文档 | P0 | 两本书均能解析 |

| FR-004 | **文档类型判定基于 manifest `media-type`，不得依赖扩展名** | P0 | EPUB 3 参考书 25 个无扩展名文档全部正确识别（对应 I-1） |
| FR-005 | 资源路径按 OPF 所在目录为基准解析相对路径（如 `EPUB/package.opf` → `EPUB/images/x.jpg`）；**文档自己声明的 `<base href>` 优先**——以 `/` 结尾当目录、否则取其所在目录（浏览器的规则），该文档内的图片与链接都按重定后的基准解析 | P0 | 图片全部命中；`test_sanitizer.py` 的三种 `<base>` 写法（缺陷 19） |

### 5.2 目录与导航

| ID | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| FR-009 | 读取 EPUB3 `nav.xhtml` 里的 **landmarks 导航**（`epub:type="landmarks"`）：每行保留 `epub:type`（`cover` / `bodymatter` / `toc` …）、标题与 `href` + `#frag`。**只认自己声明了 `landmarks` 的那个 `<nav>`**，没有声明时返回空——拿目录文档凑数等于把「目录页」当成正文起点。三本参考书都没有 landmarks，故为 `()`；解析不了的文档也返回空而不是抛异常（缺陷 18） | P2 | `test_toc.py`：`parse_landmarks()` 读出类型与锚点、无 landmarks 文档为 `()`、`book.landmarks` 与目录互不串（导航文档里的 landmarks 不会被当成目录项） |
| FR-010 | EPUB3：解析 `nav.xhtml`（`properties="nav"`）作为目录。**不要求文档合法**：裸 `&`、未闭合的 `<li>`、只有平铺的 `<a>`、`<ul>` 嵌套、没有任何 `<nav>` 声明 `epub:type`、文档自己声明非 UTF-8 编码（`<?xml … encoding="gbk"?>`）都要读出条目——先按 XML 读，失败就交给容错读取器（`html.parser`，也就是浏览器的做法），解码一律尊重文档自己的声明 | P0 | EPUB 3 参考书正确；`test_toc.py` 的六种畸形文档各一条用例（缺陷 18、23） |
| FR-011 | EPUB2：解析 `toc.ncx`（`application/x-dtbncx+xml`）作为目录；**`spine@toc` 指到的 NCX 即使 media-type 写错（或缺失）也照读**——那是书自己写明的指针。未闭合的 `navPoint`、`gbk` 声明同样容错读取 | P0 | EPUB 2 参考书正确；合成书把 NCX 的 media-type 写错仍读得出目录（缺陷 20、18、23） |
| FR-012 | 目录**优先 nav、其次 ncx**；**书没点名的节由该节自己补一行**：每节以「自己说的第一句话」命名——发布者标了 `h1`–`h6` 就用那个标题（长度与标点都不限），否则取首个文本行，且须**短、且不含句读**（像标题而不像句子：图注、出版者行不成名），取不到名字的节（纯图封面、整节无文本）不出行；补出的行按**阅读顺序**插在其前后目录项之间、层级与所处部分一致，`linear="no"` 的文档不出行（与 FR-016 同一顺序），并同样参与按位置判定的高亮（FR-017）。书完全没有任何目录数据时即此规则的退化情形：每节一行，因此不再需要单独的 `h1`/`h2` 启发式；**书写了目录、却只画一层**（`ol` / `navPoint` 全在第一层）时，层级按**每节自己写的标题**（`h1`–`h6`）还原，且只比**相对深浅**（最浅的标题即顶层，整本 `h2` 的书不整体缩进）、没有标题的行跟随其后第一个声明者的层级、深度截平在 5 层；书自己画了树就一律照办（ADR-020） | P1 | `test_toc.py`：合集参考书 135 节 / NCX 只有 3 条 → 134 行且目标升序、无重号；纯图封面与图注不成行；嵌套 NCX 下补出的行落在所属部分内且层级正确；平铺目录按标题还原成树（相对深浅、非标题行不成父项 / 跟随其后的声明者、书自己画的树不被重读、平铺目录里补出的行进入上一行）；`test_toc_panel.py` 真点击补出的行落到该节；EPUB 3 参考书 26 行 → 8 个顶层行 + 18 章、EPUB 2 参考书仍平铺 30 行（ADR-020） |
| FR-013 | 支持多层目录（`ol` 嵌套 / `navPoint` 嵌套 **，以及书只画一层时按各节标题层级还原出的树**，ADR-020），UI 缩进展示；**打开书时目录栏默认展开**（书没有目录时不出现），并**一直留在屏幕上**——点目录项跳转、滚动正文、开关大纲栏都不会把它收起，只有显式操作（`T` / 状态栏按钮 / `Esc` / 右键菜单）才收起；**状态栏左下角常驻「目录」按钮**（开栏时填充强调色、关栏时描边，右端标出 `T`；无书或书无目录时整块置灰），使「不知道有 `T` 键」的读者也能一键显示或隐藏目录 | P1 | 嵌套层级正确（含平铺书还原出的树：EPUB 3 参考书左栏在三个部分之下缩进列出 18 章，`test_toc_panel.py`）；打开 EPUB 3 参考书后左栏可见；点章节后左栏仍在；按钮单击即切换；在 134 行的合集参考书里滚到中段点一项或按 `]` 换章，左栏的滚动位置都留在原处（缺陷 25） |
| FR-014 | 目录项可跳转到目标节，并**精确到节内锚点**：`href` 解析到节（`section_index_for_href` 忽略 `#frag`），`#frag` 单独保存为 `TocEntry.fragment`，跳转时用 `LaidOutSection.anchor_block()` 定位到块。锚点落在不产生块的元素上时归**其后的第一个块**（`<div id>` 包住整段、空 `<p id>` 标记、空 `<a id>`——EPUB2 的 `filepos` 标记全是这种写法），文档末尾的标记归最后一个块；格式不合法而走容错解析路径的文档同样抽取 `id` | P0 | `test_toc.py`（两种目录格式的解析与节号解析）、`test_sanitizer.py`（锚点归属的 6 种情形）、`test_toc_panel.py`（真点击目录项后落在锚点所在块） |
| FR-015 | ~~点击目录项后侧栏自动收起~~ —— **已由 ADR-014 作废**：目录栏占正文空间而非浮层，点击后不收起（连续跳转更顺；要收起按 `T`、状态栏按钮或 `Esc`） | P1 | `test_toc_panel.py` 断言跳转后左栏仍在 |

## 6. 非功能需求（全部可测量）

### 6.1 性能

| ID | 指标 | 目标值 | 底线值 | 测量方法 |
|---|---|---|---|---|
| NFR-001 | 冷启动到首屏可见 | **0.5 s** | 1.0 s | `Controller.startupMs`（进程内计时）+ 真实后端实测 |
| NFR-002 | **本应用内存增量**（打开 85MB 书、滚动 50 屏后，减去空白 QML 窗口基线） | **100 MB** | 150 MB | `/proc/self/status` VmRSS 差值 |
| NFR-002b | 仅供参考：GPU 路径总 VmRSS（**含图形驱动栈基线，不可跨机比较**） | — | 500 MB | 同上 |
| NFR-003 | 单节排版总耗时（把 22,051 字的目标节排成**一条连续列**），稳态 | **30 ms** | 50 ms | `QElapsedTimer` |
| NFR-004 | 单个**窗口**光栅化耗时（QTextDocument → QImage，高 = 页框高 + 32px 量子） | **15 ms** | 20 ms | `QElapsedTimer` |
| NFR-005 | 连续滚动帧率（**同一量子内的滚动不回调 Python**，动画期间只做位图源矩形平移） | **60 fps** | 30 fps | QML `FrameAnimation` 计数 |
| NFR-006 | 图片单张解码耗时（208KB / 900×1400 JPEG） | **10 ms** | 25 ms | `QElapsedTimer` |
| NFR-007 | 图片常驻内存峰值（解码后位图） | **30 MB** | 50 MB | 缓存计量 |
| NFR-008 | 全书文本解析耗时（27 节） | **200 ms** | 500 ms | 边解析边计时 |

> **指标推导依据（防止拍脑袋）**
> - NFR-003：22,051 字 ≈ 100 段。Qt 富文本布局吞吐实测量级为每秒数百万字符，故 30ms 有充分余量。
> - NFR-004：一个窗口约 700–900 字（页框高 + 32px），光栅化主要是字形缓存命中后的合成，15ms 是保守值。
> - NFR-005：量子对齐后，同一量子内的滚动只是 `PageItem.pan` 平移源矩形，**完全不进 Python**；需要新位图时才付 NFR-004 的代价。
> - NFR-007：408 × 900×1400×4B = **2.0 GB** 全解码体积 → 必须 LRU，30MB 约等于 6–8 张全尺寸位图。
> - NFR-002：PySide6-Essentials 空载基线约 60–80MB，故 150MB 目标含义是「书稿与图片额外占用 < 70MB」。
